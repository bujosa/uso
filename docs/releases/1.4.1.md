# Uso 1.4.1

Uso stops asking for Claude Code keychain access after Claude Code sits idle. The Claude row keeps its last reading until you use Claude Code again.

## Install

Paste this in Terminal. It picks the build for your chip, checks the checksum and signature, installs Uso in `~/Applications`, and opens it without the Privacy & Security step:

```sh
curl -fsSL https://raw.githubusercontent.com/bujosa/uso/main/scripts/get.sh | bash
```

Or pick the zip for your Mac. Apple menu > About This Mac shows a Chip (Apple M…) or a Processor (Intel).

- **Apple silicon:** `Uso-1.4.1-macOS-apple-silicon.zip`
- **Intel:** `Uso-1.4.1-macOS-intel.zip`

Unzip it and move `Uso.app` to Applications. Quit the previous copy before replacing it. Open Uso and look in the menu bar.

macOS 14 or later. The app is locally signed and is not Apple-notarized. If macOS blocks its first launch, open System Settings > Privacy & Security and click Open Anyway; on macOS 14 you can instead right-click the app and choose Open. Each zip has a `.sha256` checksum.

## Changes

- **No repeated keychain prompts.** Claude Code's session lasts about 8 hours and renews only while Claude Code runs. Once it expired, Uso treated it as missing keychain access and asked for Always Allow. Allowing access then read the same expired session, and Claude Code's next renewal dropped the permission, so the prompt came back. Uso now recognizes an expired session and never asks for access because of it.
- **Idle Claude Code keeps its numbers.** No sign-in is needed. The Claude row keeps its last reading, labeled "Claude Code is idle. Usage updates the next time you use it.", and refreshes on its own once Claude Code renews the session. Right after Uso launches there is no earlier reading yet, so the row shows only that note.
- A current `~/.claude/.credentials.json` still wins over an expired keychain session.

## Validation

- `swift test`: 61 tests in 6 suites passed. New `ClaudeSessionTests` cover:
  - An expired session makes no keychain call, with or without a prompt.
  - A current session needs no prompt.
  - A current credentials file wins over an expired keychain session.
  - An expired session keeps the last reading without asking to sign in.
- `swift format lint --strict` on Sources, Tests, and `Package.swift` passed. CI passed on the pull request.
- Live: a build that was never granted keychain access read Claude through `/usr/bin/security` without a dialog.
- Not reproduced live with a real expired token: this Mac's token renews continuously.

## Compatibility

No migration is required. Uso still does not refresh Claude tokens or write the keychain.
