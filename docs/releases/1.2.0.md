# Uso 1.2.0

Intel Macs, Cursor and Grok Bot working again, and a panel that shows only what you use.

## Install

Paste this in Terminal. It picks the build for your chip, checks the checksum and signature, installs Uso in `~/Applications`, and opens it without the Privacy & Security step:

```sh
curl -fsSL https://raw.githubusercontent.com/bujosa/uso/main/scripts/get.sh | bash
```

Or pick the zip for your Mac. Apple menu > About This Mac shows a Chip (Apple M…) or a Processor (Intel).

- **Apple silicon:** `Uso-1.2.0-macOS-apple-silicon.zip`
- **Intel:** `Uso-1.2.0-macOS-intel.zip`

Unzip it and move `Uso.app` to Applications. Quit the previous copy before replacing it. Open Uso and look in the menu bar.

macOS 14 or later. The app is locally signed and is not Apple-notarized. If macOS blocks its first launch, open System Settings > Privacy & Security and click Open Anyway; on macOS 14 you can instead right-click the app and choose Open. Each zip has a `.sha256` checksum.

## Changes

- **Intel Macs:** Uso now runs natively on Intel. The release has one download per chip, both cut from the same universal build. Packaging stops if either architecture is missing.
- **Cursor and Grok Bot:** Cursor 3.27 seals its desktop sign-in, so Uso was sending an unreadable token and showed "session expired" or "session rejected". Uso no longer sends a sealed token. It reads the Cursor CLI's keychain session instead, through the same no-prompt path it uses for Claude, and tries the next session when Cursor rejects one. Run `cursor-agent login` once if Cursor shows Sign in needed.
- **Only what you use:** a source appears once Uso finds a session for it on this Mac. Sources you don't use no longer fill the panel and menu bar with "No session" rows. The last check is remembered, so the panel opens with the right rows before the next check finishes.
- **Needs attention:** an expired or rejected session (Grok, Grok Bot, Cursor, Codex, Claude) stays visible as Sign in needed, with the command to fix it.
- **Grok Bot** appears only once the Grok Bot app has run on this Mac, because any Cursor account answers the Grok Bot quota request.
- **OpenCode** without a Go key appears only with local activity in the last 30 days.
- **Settings:** switching a source on or off overrides detection. Show detected only clears those overrides. Show all sources shows every source, found or not.

## Validation

- `swift test`: 41 tests in 5 suites passed, adding Cursor session choice, source detection, override, upgrade, and last-detection coverage.
- The same 41 tests passed on the x86_64 slice under Rosetta (`swift build --build-tests --arch x86_64`, run with the universal `xctest`).
- Universal release build: `lipo` reports `x86_64 arm64`; both slices have a macOS 14.0 minimum.
- Each zip: one architecture only (`arm64` or `x86_64`), matching `LSArchitecturePriority`, version 1.2.0, local code signature, ZIP integrity, and `shasum -a 256 -c` passed.
- Live readings from each unzipped app (Intel under Rosetta): all six sources read, including Cursor and Grok Bot through the Cursor CLI session. The Intel app's first launch couldn't reach the five network sources once, with two VPNs connected. Three runs after that read all six.
- `swift-format lint --strict` on every changed file except `UsageService.swift`, which was not format-clean before this release (findings went from 109 to 101). `git diff --check` passed.

## Compatibility

No credential migration is required. Sources you hid before stay hidden. Every other source now follows detection. Turn a source on in Settings to keep showing it when Uso can't find a session for it. Provider usage endpoints are internal interfaces and can change.
