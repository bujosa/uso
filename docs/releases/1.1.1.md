# Uso 1.1.1

Reliable account refreshes and clearer reading times. Muse and Muse Code support are removed for now.

## Install

Download `Uso-1.1.1-macOS.zip`, unzip it, and move `Uso.app` to Applications. Quit the previous copy before replacing it. Open Uso and look in the menu bar.

Apple silicon, macOS 14 or later. The app is locally signed and is not Apple-notarized; if macOS blocks its first launch, right-click the app and choose Open.

## Changes

- **Muse:** remove both integrations from the panel, menu bar, account settings, and background readers. Uso no longer reads their credentials or requests their usage.
- **Refresh reliability:** direct Keychain reads wait up to 3 seconds in the background or 30 seconds for a manual permission request. An unresponsive system call no longer leaves refresh running indefinitely. Repeated checks do not start duplicate pending reads.
- **Account states:** a Claude session read timeout shows Not verified and can be retried. Keychain permission actions use an explicit account state instead of matching notification text.
- **Reading times:** Settings shows the last reading for every supported account, including the date for older readings.
- **Version metadata:** Claude requests use the packaged Uso version in their user agent.

Grok, Grok Bot, Cursor, Codex, Claude, and OpenCode remain supported, with independent panel and menu-bar visibility controls and the existing panel opening animation.

## Validation

- `swift test`: 31 tests in 4 suites passed, covering quota parsing, session rotation, rate limits, source freshness, preferences, and credential read deadlines.
- Scoped `swift-format lint --strict` and `git diff --check`: passed.
- Release build, local code signature, property list, and ZIP integrity: passed.
- Native panel and Settings review: all six supported sources are present; Muse and Muse Code are absent.
- Live provider reads and OpenCode local activity were checked.

## Compatibility

No credential or preference migration is required. Existing visibility preferences are preserved; saved Muse visibility IDs are ignored. Provider usage endpoints are internal interfaces and can change.
